# Roadmap

- [x] MQTT 3.1/3.1.1 TCP packet codec
- [x] Session/subscriptions/wildcards/QoS 0–2 basic/retained/will/keepalive
- [x] Auth & ACL hook interfaces
- [x] TCP/TLS/WS/WSS transport via gnety (`RawHandler`); MQTT codec/state machine in gmqx
- [x] Connect modes (UNIQUE/KICK), limits, connection rate limiting, metrics hooks
- [x] TLS / WebSocket / WSS listeners
- [x] MQTT 5 handshake, property skipping and basic reason codes
- [x] MQTT 5: CONNACK capabilities, Topic Alias, User Property forwarding, subscription options
- [x] Persistent-session storage behind the `SessionStore` seam, bounded offline queue, MQTT 5 session expiry and a bounded sweeper
- [x] Outbound QoS 1/2 retransmission (DUP, PUBREL retries, one timer per connection) and inflight windows in both directions
- [x] Bounded per-connection inflight queue (a window-full delivery waits instead of being dropped)
- [x] One writer goroutine per connection, bounded outbound queue and a write deadline per packet
- [x] CONNECT-phase read deadline and authorization timeouts (`ConnectTimeout`, `AuthTimeout`)
- [x] Shared subscriptions (`$share/{ShareName}/{filter}`): validated per §4.8.2, one live member per group round robin, one node per group across a cluster (origin-side election over the advertised groups), no retained replay and no shared offline queue
- [x] Subscription identifiers (SUBSCRIBE property 0x0B): stored with the subscription, round-tripped through the `SessionStore`, attached to live, retained-replay, offline-queue and shared-group deliveries, deduplicated and capped per delivery
- [x] MQTT 5 Will Delay Interval (cancelled by resume, cut short by session expiry, bounded by `MaxWillDelayInterval`)
- [x] MQTT 5 enhanced authentication (AUTH): `AuthExchange` SPI (`Begin`/`Continue`) with `Config.Authenticator`/`AuthMethods`, CONNACK method echo, identity precedence over `AuthManager`, re-authentication on a live connection, bounded steps and deadlines
- [x] Retained message expiry (MQTT 5 Message Expiry Interval, replayed decremented, deleted when elapsed)
- [x] Takeover parity across nodes (connect-time kick in both connect modes, DISCONNECT 0x8E) and the `NotKickSeconds` anti-flap window
- [x] Kick epochs: a kick names the node and the connect time of the connection that produced it, so a delayed kick cannot close a newer connection, and the anti-flap window applies on the receiving side too
- [x] Redis-backed shared session store (`NewRedisSessionStore`, atomic take, per-key TTL from the session expiry, namespace-scoped keys) so a client that reconnects to another node resumes its session
- [x] MQTT 5 Receive Maximum in both directions: the client's CONNECT value caps the outbound windows (shared by QoS 1 and QoS 2, queue instead of drop), and the broker's own receive maximum (default 64, advertised) is enforced on inbound publishes (QoS 1 left unacknowledged, QoS 2 refused with PUBREC 0x97)
- [x] MQTT 5 client Maximum Packet Size: every packet is measured before it is written, and one that does not fit (PUBLISH, retained replay, control packet) is dropped with `max_packet_size_too_large` instead of being split or truncated
- [x] QoS 2 state across a reconnect: inbound packet ids pending PUBREL and unconfirmed outbound exchanges are stored with the session (`SessionState.InboundQoS2`/`SessionState.Inflight`), resumed per §4.4, and dropped when the session ends
- [x] Byte-rate shaping: per-connection and broker-wide read/write token buckets that delay the excess (bounded by the write/keep-alive deadlines), count throttled bytes, and leave normal traffic untouched at their defaults
- [x] Listener port fallback (`PortFallback`, default 16) for TCP/TLS/WS/WSS: the bind is the probe, `Addrs()` reports the port that was really bound
- [x] Cluster interface + cross-node publish/kick hooks (in-memory)
- [x] Built-in TCP cluster backend (static seeds, cross-node publish/kick, reconnect)
- [x] Cluster membership (handshake, heartbeats, eviction, duplicate collapse), event dedup, subscription-aware directed routing
- [x] Redis cluster backend (per-node channels, TTL membership in Redis, directed routing)
- [x] Subscription index for local routing (literal filters in a map, wildcard filters per distinct filter; the publish path never calls `SessionStore`)
- [x] Directed publish to a client id (`PublishToClient`) with Redis client-id presence and the TCP broadcast fallback
- [x] Gossip cluster backend (SWIM membership, epidemic dissemination, gossiped summaries and client-id presence) and it is the default backend
- [x] MQTT client library (`client/`): MQTT 3.1.1/5, QoS 1/2 state machines in both directions with DUP/PUBREL retransmission and inflight windows, reconnection with backoff and subscription restore, keepalive, MQTT 5 properties, bounded ordered writer/delivery queues
- [ ] Core conformance tests (mosquitto/paho clients)
- [ ] Benchmarks and soak tests
- [ ] v1.0 API stabilization
